# 1. Что такое коллекция

**Коллекция** — объект, предназначенный для хранения нескольких объектов или доступа к набору элементов.

Основные встроенные коллекции:

```python
[1, 2, 3]                  # list
(1, 2, 3)                  # tuple
{1, 2, 3}                  # set
{"id": 1, "name": "Bob"}   # dict
```

Они существуют не как четыре варианта записи «много данных». У каждой своя модель:

```text
list  → порядок + индексы + изменение
tuple → порядок + фиксированная структура
set   → уникальность + быстрый membership
dict  → ключ → значение + быстрый lookup по ключу
```

Выбор структуры влияет на корректность, читаемость, память и скорость алгоритма.

## Sequence

**Последовательность** — объект с упорядоченными позициями элементов.

Примеры:

```python
list
tuple
str
range
```

Для sequence естественны:

```python
items[0]
items[-1]
items[1:5]
```

## Mapping

**Mapping** хранит соответствия:

```text
ключ → значение
```

Главный встроенный mapping:

```python
dict
```

```python
user = {
    "id": 10,
    "name": "Alice",
}
```

Доступ:

```python
user["name"]
```

а не по позиции.

## Set-like структура

`set` моделирует математическое множество:

- элементы уникальны;
- индексного доступа нет;
- основной вопрос — «есть ли этот элемент?»;
- есть пересечение, объединение и разность.

# 2. `list`: список

`list` — **изменяемая упорядоченная последовательность**.

Разберём определение:

- **упорядоченная** — порядок элементов сохраняется и имеет смысл;
- **последовательность** — есть позиции, индексы и срезы;
- **изменяемая** — после создания элементы можно добавлять, удалять и заменять.

```python
users = ["Alice", "Bob", "Charlie"]
```

Повторы разрешены:

```python
numbers = [1, 1, 2, 2, 3]
```

Python позволяет смешивать типы:

```python
data = [1, "hello", True, None]
```

но в рабочем коде обычно лучше, когда коллекция имеет однородный предметный смысл.

## Как list устроен концептуально

В CPython `list` реализован примерно как динамический массив ссылок на объекты.

Это помогает понять:

```python
items[index]
```

быстрый, а:

```python
items.insert(0, value)
```

может потребовать сдвига множества элементов.

Это деталь CPython, а не определение языка Python, но полезная mental model.

# 3. Индексы и срезы

```python
users = ["Alice", "Bob", "Charlie"]
```

Индексы:

```text
0 → Alice
1 → Bob
2 → Charlie
```

```python
users[0]
# 'Alice'
```

## Отрицательные индексы

```python
users[-1]
# 'Charlie'
```

```python
users[-2]
# 'Bob'
```

## Ошибка индекса

```python
users[100]
```

даёт:

```text
IndexError: list index out of range
```

## Срез

```python
items[start:stop:step]
```

`stop` не включается.

```python
numbers = [0, 1, 2, 3, 4, 5]

numbers[1:4]
# [1, 2, 3]
```

Почему `stop` не включается? Python часто использует интервалы вида:

```text
[start, stop)
```

Тогда длина:

```python
items[2:5]
```

равна:

```text
5 - 2 = 3
```

## Пропущенные параметры

```python
items[:5]
items[5:]
items[:]
items[::2]
items[::-1]
```

`items[::-1]` создаёт новый список в обратном порядке.

## Срез создаёт новый внешний список

```python
a = [1, 2, 3]
b = a[:]

print(a == b)
# True

print(a is b)
# False
```

Но это **shallow copy**:

```python
a = [[1], [2]]
b = a[:]

b[0].append(100)

print(a)
# [[1, 100], [2]]
```

Внешние списки разные, вложенные объекты общие.

Срез из `k` элементов требует создать новый list, поэтому его стоимость примерно:

```text
O(k)
```

# 4. Mutation, rebinding и aliasing

Это фундамент для коллекций.

## Mutation

**Mutation** — изменение существующего объекта.

```python
items = [1, 2]
items.append(3)
```

Список тот же объект, но состояние изменилось.

## Rebinding

**Rebinding** — имя начинает ссылаться на другой объект.

```python
items = [100]
```

Старый list не «превратился» в новый. Имя `items` просто переключилось.

## Aliasing

**Aliasing** — несколько имён или путей доступа ведут к одному mutable-объекту.

```python
a = [1, 2]
b = a
```

Теперь:

```python
b.append(3)
```

видно через:

```python
a
# [1, 2, 3]
```

Но:

```python
b = [100]
```

не меняет `a`, потому что это rebinding имени `b`.

Главный вопрос при чтении кода:

> сейчас меняют существующий объект или переназначают имя?

# 5. `append`, `extend`, `insert`

## `append`

Добавляет **один объект** в конец.

```python
items = [1, 2]
items.append(3)

print(items)
# [1, 2, 3]
```

Если объект сам list:

```python
items.append([3, 4])
```

получим:

```python
[1, 2, [3, 4]]
```

## `extend`

Берёт iterable и добавляет его элементы по одному:

```python
items = [1, 2]
items.extend([3, 4])

print(items)
# [1, 2, 3, 4]
```

Mental model:

```text
append(x) → добавить x как один элемент
extend(x) → пройти по x и добавить его элементы
```

## `insert`

```python
items.insert(index, value)
```

```python
items = [1, 3]
items.insert(1, 2)

print(items)
# [1, 2, 3]
```

Вставка в начало/середину может требовать сдвига элементов:

```text
O(n)
```

А `append` обычно имеет амортизированную сложность:

```text
O(1)
```

# 6. Методы in-place и `None`

Очень важное соглашение Python: методы, которые очевидно изменяют коллекцию in place, часто возвращают `None`.

```python
items = [1, 2]

result = items.append(3)

print(items)
# [1, 2, 3]

print(result)
# None
```

Классическая ошибка:

```python
items = items.append(3)
```

Теперь имя `items` связано с:

```python
None
```

Похожее поведение имеют:

```python
append
extend
insert
sort
reverse
clear
```

Нельзя автоматически ожидать, что mutating method вернёт изменённый контейнер.

# 7. Удаление: `remove`, `pop`, `del`, `clear`

## `remove(value)`

Удаляет первое значение, равное `value`.

```python
numbers = [1, 2, 1, 3]

numbers.remove(1)

print(numbers)
# [2, 1, 3]
```

Если значения нет:

```text
ValueError
```

Не всегда нужно заранее делать `if value in items`. Если отсутствие значения — нарушение контракта, ошибка может быть полезна.

## `pop(index)`

Удаляет по позиции и **возвращает удалённый элемент**.

```python
users = ["Alice", "Bob", "Charlie"]

removed = users.pop(1)

print(removed)
# Bob
```

Без аргумента:

```python
users.pop()
```

удаляется последний элемент.

`pop()` с конца обычно:

```text
O(1)
```

А:

```python
items.pop(0)
```

обычно:

```text
O(n)
```

потому что оставшиеся элементы логически сдвигаются.

## `del`

```python
del items[2]
```

Можно удалить срез:

```python
del items[2:5]
```

## `clear`

```python
items.clear()
```

очищает **существующий** list.

Важная разница:

```python
a = [1, 2]
b = a
```

После:

```python
a.clear()
```

`b` тоже видит пустой list.

А:

```python
a = []
```

лишь перепривязывает имя `a`; `b` остаётся со старым объектом.

# 8. Membership и поиск

Оператор:

```python
in
```

проверяет принадлежность.

Для list:

```python
3 in [1, 2, 3]
# True
```

List обычно проверяет элементы последовательно:

```text
O(n)
```

## `not in`

```python
3 not in [1, 2]
# True
```

## `index`

```python
items.index(value)
```

возвращает индекс первого совпадения.

Если нет — `ValueError`.

## `count`

```python
items.count(value)
```

считает число совпадений и требует пройти по списку:

```text
O(n)
```

## Почему repeated membership в list опасен

```python
seen = []

for item in values:
    if item not in seen:
        seen.append(item)
```

По мере роста `seen` каждая проверка становится длиннее. В худшем случае алгоритм приближается к:

```text
O(n²)
```

Для membership-heavy задач часто нужен `set`.

# 9. Сортировка

## `list.sort()`

Меняет текущий list:

```python
numbers = [3, 1, 2]
numbers.sort()

print(numbers)
# [1, 2, 3]
```

Возвращает:

```python
None
```

## `sorted()`

Создаёт новый list:

```python
numbers = [3, 1, 2]

result = sorted(numbers)

print(numbers)
# [3, 1, 2]

print(result)
# [1, 2, 3]
```

`sorted()` принимает любой iterable и всегда возвращает list.

## `reverse=True`

```python
sorted(numbers, reverse=True)
```

## `key`

`key` — функция, которая для каждого элемента вычисляет значение сортировки.

```python
users = [
    {"name": "Alice", "age": 30},
    {"name": "Bob", "age": 22},
]

sorted_users = sorted(
    users,
    key=lambda user: user["age"],
)
```

## Несколько критериев

```python
sorted(
    tickets,
    key=lambda ticket: (
        ticket["priority"],
        ticket["created_at"],
    ),
)
```

Tuple сравнивается поэлементно: сначала `priority`, затем `created_at`.

## Stable sort

Python sort **стабилен**: элементы с одинаковым ключом сохраняют взаимный порядок.

Это гарантированное свойство.

## Сложность

Для обычной оценки:

```text
sorting ≈ O(n log n)
```

Поэтому если нужен один максимум, не сортируй весь список:

```python
max(orders, key=lambda order: order["amount"])
```

обычно требует один проход:

```text
O(n)
```

# 10. Обход: `for`, `enumerate`, `zip`

Если индекс не нужен:

```python
for user in users:
    print(user)
```

Не нужно автоматически писать:

```python
for i in range(len(users)):
    print(users[i])
```

## `enumerate`

Если нужен индекс:

```python
for index, user in enumerate(users):
    ...
```

Для человеческой нумерации:

```python
for number, user in enumerate(users, start=1):
    print(number, user)
```

## `zip`

Идёт по iterable параллельно:

```python
names = ["Alice", "Bob"]
ages = [30, 22]

for name, age in zip(names, ages):
    print(name, age)
```

Обычный `zip` останавливается по кратчайшему iterable.

Если длины обязаны совпадать:

```python
zip(names, ages, strict=True)
```

при несоответствии выбросит `ValueError`.

# 11. `tuple`: кортеж

`tuple` — **упорядоченная неизменяемая последовательность**.

```python
point = (10, 20)
```

Нельзя:

```python
point[0] = 100
```

## Главный смысл tuple

Не «он немного быстрее list», а:

> эта последовательность структурно фиксирована.

Примеры:

```python
coordinates = (55.75, 37.61)
rgb = (255, 120, 20)
```

## Один элемент

```python
value = (1,)
```

Tuple определяет запятая.

```python
(1)
```

это просто `int`.

## Вложенный mutable объект

```python
data = ([1, 2], "hello")

data[0].append(3)
```

работает.

Сам tuple не изменился: он всё ещё содержит ту же ссылку на тот же list. Изменилось состояние вложенного объекта.

## Hashability tuple

Tuple hashable только если все его элементы hashable.

```python
(1, 2, "x")
```

может быть ключом dict.

А:

```python
([1, 2], 3)
```

нет, потому что внутри unhashable list.

# 13. `set`: множество

`set` — **изменяемая коллекция уникальных hashable-элементов**.

```python
ids = {10, 20, 30}
```

## Повторы исчезают

```python
ids = {1, 1, 2, 2, 3}

print(ids)
# {1, 2, 3}
```

## У set нет индексов

```python
ids[0]
```

даст:

```text
TypeError
```

Set не моделирует «первый, второй, третий элемент».

Его основной смысл:

```text
элемент есть / элемента нет
```

Не полагайся на порядок итерации `set` как на часть контракта программы.

Даже если в конкретном запуске порядок выглядит стабильным, язык не гарантирует insertion order для set.

Если порядок важен — используй структуру, где он является частью модели.

## Пустой set

```python
{}
```

это пустой `dict`.

Пустой `set`:

```python
set()
```

# 14. Hashability

Это одно из центральных понятий Python collections.

## Что такое hash

Функция:

```python
hash(obj)
```

возвращает целое число — hash объекта.

Hash table использует его, чтобы быстро определить, где искать ключ или элемент.

## Hashable object

Упрощённо hashable-объект:

- имеет hash;
- hash остаётся стабильным, пока объект используется как ключ/элемент hash table;
- корректно поддерживает сравнение равенства.

Обычно hashable:

```python
int
float
str
bytes
frozenset
```

Tuple hashable только если **все его элементы** hashable.

Обычно unhashable:

```python
list
dict
set
```

потому что они изменяемые.

## Почему mutable object опасен как ключ

Представь:

1. dict вычислил `hash(key)`;
2. положил запись в соответствующий bucket;
3. key изменился;
4. его hash тоже потенциально мог бы измениться.

Тогда структура могла бы потерять собственный ключ.

Поэтому mutable built-in контейнеры не разрешены как обычные dict keys / set elements.

## Ошибка

```python
items = {[1, 2]}
```

даст:

```text
TypeError: unhashable type: 'list'
```

## Связь `hash` и `==`

Важный контракт:

> если `a == b`, то `hash(a)` и `hash(b)` должны совпадать.

Обратное неверно:

> одинаковый hash не гарантирует `a == b`.

Возможны **hash collisions**.

Python умеет их обрабатывать, дополнительно сравнивая объекты.

# 15. Membership в set

```python
user_id in user_ids
```

для set в среднем:

```text
O(1)
```

Это и есть главный practical win.

Сравни:

```python
processed_ids = []
```

и:

```python
processed_ids = set()
```

Если проверка:

```python
order_id in processed_ids
```

делается тысячи раз, set обычно значительно уместнее.

Теоретически worst-case может быть хуже из-за коллизий, но для прикладной оценки:

```text
set membership ≈ O(1) average
```

— правильная mental model.

# 19. `dict`: отображение ключ → значение

`dict` — изменяемый mapping:

```python
key → value
```

Пример:

```python
user = {
    "id": 10,
    "name": "Alice",
}
```

Главная mental model:

```text
list → найти по позиции
dict → найти по ключу
```

## Ключи уникальны

```python
data = {
    "id": 1,
    "id": 2,
}
```

Итог:

```python
{"id": 2}
```

Последнее значение для одинакового key заменяет предыдущее.

## Значения могут повторяться

```python
data = {
    "a": 1,
    "b": 1,
}
```

Нормально.

## Порядок dict

Современный Python гарантирует insertion order словаря.

С Python 3.7 это часть языковой спецификации.

```python
data = {}

data["a"] = 1
data["b"] = 2
data["c"] = 3
```

Итерация сохранит:

```text
a
b
c
```

Но dict всё равно выбирают прежде всего ради модели `key → value`, а не как замену list.

## Ключи должны быть hashable

Можно:

```python
{
    1: "number",
    "id": "string",
    (1, 2): "tuple",
}
```

# 26. Индексирование объектов

Допустим, есть:

```python
users = [
    {"id": 10, "name": "Alice"},
    {"id": 20, "name": "Bob"},
]
```

Если постоянно искать пользователя по id циклом:

```python
for user in users:
    if user["id"] == target_id:
        ...
```

каждый lookup:

```text
O(n)
```

Можно один раз построить индекс:

```python
users_by_id = {
    user["id"]: user
    for user in users
}
```

Теперь:

```python
users_by_id[target_id]
```

в среднем:

```text
O(1)
```

Trade-off:

```text
больше памяти
↓
быстрее repeated lookup
```

# 27. Comprehensions

Comprehension — синтаксис создания коллекции из iterable.

## List comprehension

```python
squares = [
    x * x
    for x in range(5)
]
```

Результат:

```python
[0, 1, 4, 9, 16]
```

## С фильтром

```python
even = [
    x
    for x in range(10)
    if x % 2 == 0
]
```

## Set comprehension

```python
lengths = {
    len(name)
    for name in names
}
```

## Dict comprehension

```python
users_by_id = {
    user["id"]: user
    for user in users
}
```

## Когда comprehension хорош

Когда трансформация:

- короткая;
- очевидная;
- локальная;
- без сложных side effects.

## Когда обычный цикл лучше

Если внутри:

- много ветвлений;
- логирование;
- exceptions;
- несколько действий;
- сложное условие.

Читаемость важнее минимального числа строк.

## Не использовать comprehension ради side effects

Плохо:

```python

```

создаётся ненужный list из `None`.

Правильно:

```python
for x in items:
    print(x)
```

# 33. Изменение коллекции во время обхода

## List

```python
numbers = [1, 2, 3, 4]

for number in numbers:
    if number % 2 == 0:
        numbers.remove(number)
```

Опасно рассуждать о таком коде: при удалении элементы сдвигаются, а iterator продолжает движение.

Можно пропустить элементы.

Часто безопаснее создать новый list:

```python
numbers = [
    number
    for number in numbers
    if number % 2 != 0
]
```

## Dict/set

Менять размер во время обычной итерации:

```python
for key in data:
    del data[key]
```

может дать:

```text
RuntimeError: dictionary changed size during iteration
```

Если нужно удалить по условию:

```python
for key in list(data):
    if should_delete(key):
        del data[key]
```

Здесь `list(data)` — snapshot ключей.

# 34. Сложность основных операций

Big O описывает **как растёт работа при росте входа**, а не конкретные секунды.

## List

| Операция | Типичная сложность |
|---|---:|
| `items[i]` | `O(1)` |
| `append` | `O(1)` amortized |
| `pop()` | `O(1)` |
| `insert(0, x)` | `O(n)` |
| `pop(0)` | `O(n)` |
| `x in items` | `O(n)` |
| `index(x)` | `O(n)` |
| slice из `k` элементов | `O(k)` |
| sort | около `O(n log n)` |

## Set

| Операция | Средняя |
|---|---:|
| `x in s` | `O(1)` |
| `add` | `O(1)` |
| `remove/discard` | `O(1)` |

## Dict

| Операция | Средняя |
|---|---:|
| `data[key]` | `O(1)` |
| `data[key] = value` | `O(1)` |
| `key in data` | `O(1)` |
| `del data[key]` | `O(1)` |

Главное:

> выбор структуры данных часто важнее «оптимизации цикла».

# 37. `deque`

```python
from collections import deque
```

`deque` — double-ended queue.

Быстро работает с обоими концами.

```python
queue = deque()
```

FIFO:

```python
queue.popleft()
```


обычно:

```text

```

Для настоящей очереди `deque` обычно лучше list.

# 38. Production-паттерны

## Dedup с сохранением порядка

```python
[3, 1, 3, 2, 1, 5]
```

Результат:

```python

```

Понятный вариант:

```python
seen = set()
```

Почему две структуры?

```text
set  → быстрый membership
list → порядок результата
```

```python
processed_ids = set()

for order in orders:

    process(order)
```

Set выбран потому, что главный вопрос:

> этот ID уже встречался?

## Totals by user

```python
totals = {}

for order in orders:
    user_id = order["user_id"]
    amount = order["amount"]

    totals[user_id] = (
        totals.get(user_id, 0)
        + amount
    )
```

Dict здесь естественно моделирует:

```text
user_id → accumulated total
```

## Permissions

```python
required = {

}

actual = {
    "ticket.read",
    "ticket.write",

}
```

```python
if required <= actual:

```

Set выражает предметную модель лучше, чем list.

# 1. Имена, объекты и присваивание

## 1.1. Что такое объект

В Python почти всё, с чем ты работаешь, является объектом.

Число:

```python
10
```

Строка:

```python
"hello"
```

Список:

```python
[1, 2, 3]
```

Функция, класс, исключение — тоже объекты.

У объекта есть как минимум:

- **тип**;
- **значение или состояние**;
- **identity** — идентичность конкретного объекта во время его жизни.

---

## 1.2. Что такое имя переменной

Когда пишем:

```python
age = 23
```

удобнее думать не так:

> в коробку `age` положили число `23`.

А так:

> имя `age` теперь связано с объектом `23`.

Это очень важная модель Python.

Схематично:

```text
age ─────► 23
```

---

## 1.3. Что делает оператор `=`

Одинарный знак:

```python
=
```

— это **оператор присваивания**.

Он не означает математическое равенство.

```python
x = 5
```

значит:

> связать имя `x` с объектом `5`.

Если затем:

```python
x = 10
```

это не «изменение числа 5».

Имя `x` просто начинает ссылаться на другой объект:

```text
x ─────► 10
```

---

## 1.4. Несколько имён могут ссылаться на один объект

```python
a = [1, 2]
b = a
```

Теперь:

```text
a ─┐
   ├────► [1, 2]
b ─┘
```

Поэтому:

```python
b.append(3)

print(a)
```

получим:

```python
[1, 2, 3]
```

Почему?

Потому что список был один.

Имена `a` и `b` просто давали к нему доступ.

# 1.5. Mutable и immutable — что это вообще значит

Это фундаментальное понятие Python.

## Mutable

**Mutable object** — изменяемый объект.

Его внутреннее состояние можно изменить, не создавая новый объект.

Примеры:

```python
list
dict
set
```

Например:

```python
numbers = [1, 2]
numbers.append(3)
```

Список остался тем же объектом, но его содержимое изменилось.

---

## Immutable

**Immutable object** — неизменяемый объект.

После создания его значение нельзя изменить «на месте».

Примеры:

```python
int
float
bool
str
tuple
frozenset
NoneType
```

Например:

```python
x = 10
x += 1
```

Может казаться, что число `10` превратилось в `11`.

Но этого не произошло.

Создано/использовано другое числовое значение, а имя `x` стало ссылаться на него.

---

## Почему это вообще важно

Потому что mutable-объекты могут неожиданно изменяться через другую ссылку.

```python
a = [1, 2]
b = a

b.append(3)

print(a)
# [1, 2, 3]
```

А с immutable-объектом:

```python
a = 10
b = a

b += 1

print(a)
# 10

print(b)
# 11
```

Изменение `b` не меняет объект, связанный с `a`.

---

## Очень важное следствие

При чтении кода всегда спрашивай:

> объект изменяется или имя начинает ссылаться на новый объект?

Это два разных механизма.

---

# 1.6. Mutable не означает «плохой»

Изменяемые объекты нужны постоянно.

Например:

```python
orders = []
orders.append(new_order)
```

Это абсолютно нормально.

Проблема не в mutability.

Проблема — **не понимать, где объект изменяется и кто ещё на него ссылается**.

---

# 1.7. Копирование: почему `b = a` — не копия

```python
a = [1, 2]
b = a
```

Это две ссылки на один список.

Если нужен новый внешний список:

```python
b = a.copy()
```

или:

```python
b = a[:]
```

Теперь:

```python
a is b
```

будет:

```python
False
```

Но:

```python
a == b
```

будет:

```python
True
```

И вот здесь мы подходим к разнице `==` и `is`.

---

# 1.8. `==` и `is` — объяснение с нуля

## `==`

Оператор:

```python
==
```

спрашивает:

> эти объекты равны по значению?

Пример:

```python
a = [1, 2]
b = [1, 2]

print(a == b)
```

Результат:

```python
True
```

Списки содержат одинаковые значения.

---

## `is`

Оператор:

```python
is
```

спрашивает:

> это буквально один и тот же объект?

```python
print(a is b)
```

Результат:

```python
False
```

Потому что было создано два разных списка.

---

## Ещё пример

```python
a = [1, 2]
b = a

print(a == b)
# True

print(a is b)
# True
```

Здесь и значение одинаковое, и объект один.

---

## Когда использовать `==`

Для обычного сравнения значений:

```python
status == "paid"
age == 18
user_id == expected_id
```

---

## Когда использовать `is`

Самый важный практический случай:

```python
value is None
```

и:

```python
value is not None
```

Почему?

`None` — специальный singleton-объект.

Мы хотим проверить именно его identity.

---

## Не надо делать так

```python
status is "paid"
```

или:

```python
number is 5
```

Даже если в каком-то запуске результат выглядит ожидаемо, это неправильный смысл оператора.

Для значения:

```python
status == "paid"
```

---

# 1.9. `id()`

Функция:

```python
id(obj)
```

возвращает числовой идентификатор объекта на время его жизни.

Пример:

```python
a = []
b = a

print(id(a))
print(id(b))
```

Числа совпадут.

`id()` полезен для исследования object model, но в обычной бизнес-логике почти не нужен.

---

# 1.10. Shallow copy

**Shallow copy** — поверхностная копия.

Создаётся новый внешний контейнер, но вложенные объекты не копируются автоматически.

```python
a = [[1], [2]]
b = a.copy()
```

Схематично:

```text
a ──► [ ──► [1], ──► [2] ]
b ──► [ ──► [1], ──► [2] ]
```

Внешние списки разные.

Вложенные списки общие.

Поэтому:

```python
b[0].append(100)

print(a)
```

получим:

```python
[[1, 100], [2]]
```

---

# 1.11. Deep copy

**Deep copy** пытается рекурсивно создать копии вложенных объектов.

```python
from copy import deepcopy

b = deepcopy(a)
```

После этого изменение вложенного списка `b` обычно не затронет соответствующий вложенный объект `a`.

Но deep copy не нужно использовать автоматически.

Он:

- может быть дорогим;
- не всегда нужен;
- иногда вообще не соответствует логике предметной области.

Сначала нужно понимать, какое поведение требуется.

---

# 1.12. Tuple и «неизменяемость»

```python
data = ([1, 2], "hello")
```

`tuple` immutable.

Нельзя:

```python
data[0] = [3, 4]
```

Но:

```python
data[0].append(3)
```

можно.

Почему?

Сам tuple по-прежнему содержит ту же ссылку на тот же список.

Изменился вложенный объект.

Поэтому:

> immutable-контейнер не означает автоматически глубокую неизменяемость всего графа объектов внутри него.

---

# 1.13. Backend-пример

Пусть endpoint получил:

```python
payload = {
    "status": "PAID",
    "amount": 100,
}
```

Функция:

```python
def normalize(data):
    data["status"] = data["status"].lower()
```

изменяет исходный объект.

После:

```python
normalize(payload)
```

`payload` уже другой по состоянию:

```python
{
    "status": "paid",
    "amount": 100,
}
```

Поэтому функции должны иметь понятный контракт:

- мутируют вход;
- или возвращают новое значение.

# 4.5. Truthiness — что это

`if` не требует буквально `True` или `False`.

Python умеет интерпретировать другие объекты как истинные или ложные.

Это называется **truthiness**.

```python

None
0
0.0
""
[]
{}
```

## Truthy значения

Большинство остальных объектов:

```python

-1
"hello"
[0]
{"x": None}
```

# 5. Условия: `if / elif / else`

## 5.1. Что делает `if`


1. вычисляет `condition`;
2. определяет truthiness результата;
3. если truthy — выполняет блок.

---

# 5.2. `else`

```python
if age >= 18:
    print("adult")
else:
    print("minor")
```

`else` означает:

> ни одна предыдущая проверка цепочки не сработала.

---

# 5.3. `elif`

```python
if score >= 90:
    grade = "A"
elif score >= 75:
    grade = "B"
else:
    grade = "C"
```

Проверка идёт сверху вниз.

---

# 5.4. Выполняется первая подходящая ветка

```python
score = 95

if score >= 60:
    print("passed")
elif score >= 90:
    print("excellent")
```

Результат:

```text
passed
```

Почему?

После успешного `if` остальная цепочка не проверяется.

---

# 5.5. Порядок — часть логики

Правильнее:

```python
if score >= 90:
    ...
elif score >= 60:
    ...
```

Сначала более специфичное/строгое условие.

---

# 5.6. Несколько `if` — не то же самое

```python
if condition_a:
    ...

if condition_b:
    ...
```

Обе проверки могут сработать.

А:

```python
if condition_a:
    ...
elif condition_b:
    ...
```

после первого успеха вторая уже не выполняется.

---

# 5.7. Guard clauses

Guard clause — ранняя проверка, которая быстро исключает неподходящий сценарий.

```python
def process(order):
    if order is None:
        return None

    if order["status"] != "paid":
        return None

    if order["amount"] <= 0:
        return None

    return handle(order)
```

Преимущество:

- меньше вложенности;
- легче читать;
- ошибки и edge cases видны сверху.

---

# 6. `and / or / not` и short-circuit

## 6.1. `and`

```python
a and b
```

логически означает:

> и `a`, и `b` должны быть truthy.

Пример:

```python
if is_active and has_permission:
    ...
```

---

# 6.2. `or`

```python
a or b
```

означает:

> достаточно, чтобы хотя бы одно было truthy.

```python
if is_admin or is_owner:
    ...
```

---

# 6.3. `not`

```python
not condition
```

инвертирует truthiness.

```python
if not items:
    print("empty")
```

---

# 6.4. Как переводить бизнес-правило в условие

Фраза:

> Пропустить заказ, если он не paid ИЛИ уже обработан.

Разбиваем:

```text
условие A: status != "paid"
условие B: order_id in processed
```

Нужно пропустить, если выполняется хотя бы одно:

```python
if status != "paid" or order_id in processed:
    continue
```

---

# 6.5. Почему `and` здесь ошибочно

```python
if status != "paid" and order_id in processed:
```

означает:

> пропустить только если заказ одновременно не paid и уже обработан.

То есть неоплаченный новый заказ может пройти дальше.

Логика сломана.

---

# 6.6. Short-circuit

**Short-circuit evaluation** — раннее прекращение вычисления логического выражения, когда результат уже известен.

---

## Для `and`

```python
A and B
```

Если `A` falsy, весь результат уже falsy.

`B` не вычисляется.

---

## Для `or`

```python
A or B
```

Если `A` truthy, весь результат уже truthy.

`B` не вычисляется.

---

# 6.7. Почему это полезно

```python
if user is not None and user.is_active:
    ...
```

Если:

```python
user is None
```

вторая часть:

```python
user.is_active
```

не выполняется.

Иначе был бы:

```text
AttributeError
```

---

# 6.8. Твой случай с `None`

Безопасно:

```python
if value is not None and value < 10:
    ...
```

Сначала исключаем `None`.

Только потом сравниваем с числом.

---

# 6.9. `and` и `or` возвращают операнды

Это важная особенность.

```python
"" or "default"
```

вернёт:

```python
"default"
```

Не `True`.

---

```python
"hello" and 10
```

вернёт:

```python
10
```

Почему?

`and` и `or` возвращают тот объект, на котором результат стал определён.

Это позволяет писать:

```python
name = user_input or "Anonymous"
```

Но не злоупотребляй такими трюками, если логика становится менее очевидной.

# 9. `for` и iterable

## 9.1. Что такое `for`

Неправильная модель:

> `for` повторяет блок нужное количество раз.

Это слишком узко.

Правильнее:

> `for` последовательно получает элементы из итерируемого объекта.

---

# 9.2. Что такое iterable

**Iterable** — объект, из которого Python может получить последовательность элементов для перебора.

Примеры:

```python
list
tuple
str
dict
set
range
file
generator
```

---

# 9.3. `for` по списку

```python
users = ["Alice", "Bob"]

for user in users:
    print(user)
```

На каждой итерации имя `user` связывается с очередным элементом.

---

# 9.4. По строке

```python
for char in "abc":
    print(char)
```

---

# 9.5. По dict

```python
data = {
    "name": "Alice",
    "age": 25,
}
```

По умолчанию:

```python
for key in data:
    ...
```

идут ключи.

---

## Значения

```python
for value in data.values():
    ...
```

---

## Ключ и значение

```python
for key, value in data.items():
    ...
```

---

# 9.6. Не используй индексы без необходимости

Плохо:

```python
for i in range(len(users)):
    print(users[i])
```

Если индекс не нужен:

```python
for user in users:
    print(user)
```

Это проще и лучше выражает намерение.

---

# 9.7. `enumerate`

Если нужен индекс:

```python
for index, user in enumerate(users):
    ...
```

Если нужна человеческая нумерация:

```python
for number, user in enumerate(users, start=1):
    print(number, user)
```

---

# 9.8. Iterator — базовая идея

Iterable и iterator — не одно и то же.

**Iterable** — объект, из которого можно получить iterator.

**Iterator** — объект, который знает текущее положение и умеет выдавать следующий элемент.

Пример:

```python
items = [10, 20, 30]
iterator = iter(items)
```

Теперь:

```python
next(iterator)
# 10
```

Следующий вызов:

```python
next(iterator)
# 20
```

---

# 9.9. Как `for` работает концептуально

Этот код:

```python
for item in items:
    print(item)
```

можно приблизительно представить как:

```python
iterator = iter(items)

while True:
    try:
        item = next(iterator)
    except StopIteration:
        break

    print(item)
```

Тебе не нужно писать циклы так вручную.

Но эта mental model потом поможет понять генераторы.

# 11. `while`

## 11.1. Что такое `while`

`while` выполняет блок до тех пор, пока условие truthy.

```python
while condition:
    ...
```

---

# 11.2. Пример

```python
number = 0

while number < 3:
    print(number)
    number += 1
```

---

# 11.3. Шаги выполнения

Начало:

```python
number = 0
```

Проверка:

```python
0 < 3
```

`True`.

Печать `0`.

Увеличение до `1`.

Снова проверка.

Когда `number == 3`:

```python
3 < 3
```

`False`.

Цикл завершён.

---

# 11.4. Когда while лучше for

Когда количество итераций заранее не определяется коллекцией или диапазоном.

Примеры:

```python
while not connected:
    ...
```

```python
while queue:
    ...
```

```python
while True:
    command = input("> ")

    if command == "exit":
        break
```

---

# 11.5. Бесконечный цикл

```python
while True:
    ...
```

не является ошибкой сам по себе.

Ошибкой будет бесконечный цикл без корректного механизма завершения, если он не задуман как постоянно работающий event loop/service loop.

---

# 11.6. Классическая ошибка

```python
number = 0

while number < 10:
    print(number)
```

`number` не меняется.

Поэтому:

```python
number < 10
```

навсегда остаётся `True`.

# 12. `break / continue`

## 12.1. `break`

`break` завершает ближайший цикл.

```python
for value in values:
    if value == target:
        break
```

---

# 12.2. Зачем нужен break

Например, нашли то, что искали.

Продолжать проход бессмысленно.

```python
found = None

for user in users:
    if user["id"] == target_id:
        found = user
        break
```

---

# 12.3. `continue`

`continue` завершает текущую итерацию и начинает следующую.

```python
for order in orders:
    if order["status"] != "paid":
        continue

    process(order)
```

Неоплаченный заказ не проходит дальше.

---

# 12.4. Guard style в цикле

Вместо:

```python
for order in orders:
    if order["status"] == "paid":
        if order["amount"] > 0:
            process(order)
```

часто читаемее:

```python
for order in orders:
    if order["status"] != "paid":
        continue

    if order["amount"] <= 0:
        continue

    process(order)
```

---

# 12.5. Опасность continue в while

```python
number = 0

while number < 10:
    if number == 5:
        continue

    number += 1
```

Когда:

```python
number == 5
```

срабатывает `continue`.

Строка:

```python
number += 1
```

не выполняется.

`number` навсегда остаётся `5`.

---

# 12.6. Break во вложенных циклах

```python
for row in matrix:
    for value in row:
        if value == target:
            break
```

`break` завершит только внутренний цикл.

Внешний продолжится.

Это очень частый источник логических ошибок.

---

# 13. Вложенные циклы и сложность

## 13.1. Вложенный цикл

```python
for i in range(3):
    for j in range(2):
        print(i, j)
```

Для каждого `i` внутренний цикл полностью проходит по `j`.

---

# 13.2. Сколько итераций

```text
3 * 2 = 6
```

Но важнее научиться думать не только о конкретных числах.

---

# 13.3. Что такое сложность

Сложность показывает:

> как растёт объём работы при росте входных данных.

---

# 13.4. `O(n)`

Один проход:

```python
for item in items:
    ...
```

Если элементов стало в 10 раз больше, работы примерно в 10 раз больше.

---

# 13.5. `O(n²)`

```python
for a in items:
    for b in items:
        ...
```

Если элементов стало в 10 раз больше, количество пар может вырасти примерно в 100 раз.

---

# 13.6. `O(n * m)`

```python
for user in users:
    for order in orders:
        ...
```

Если:

```text
n = число users
m = число orders
```

то возможное число сравнений:

```text
n * m
```

---

# 13.7. Реальный пример

```python
for user in users:
    for order in orders:
        if order["user_id"] == user["id"]:
            ...
```

При:

```text
1000 users
10000 orders
```

получаем до:

```text
10 000 000
```

проверок.

---

# 13.8. Как структура данных меняет алгоритм

Строим индекс:

```python
orders_by_user = {}

for order in orders:
    user_id = order["user_id"]
    orders_by_user.setdefault(user_id, []).append(order)
```

Теперь:

```python
orders_by_user.get(user_id, [])
```

получает нужную группу без полного повторного обхода `orders`.

---

# 13.9. Главная мысль

Оптимизация — это не обязательно:

> сделать цикл «умнее».

Очень часто правильный вопрос:

> какую структуру данных использовать?

---

# 13.10. Не бойся вложенных циклов автоматически

Если матрица маленькая:

```python
for row in matrix:
    for value in row:
        ...
```

это нормальный и очевидный код.

Big O — не религия.

Это инструмент оценки.
